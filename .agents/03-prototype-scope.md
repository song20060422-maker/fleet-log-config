# 03-prototype-scope.md — 原型页面要求与范围边界

## 1. 原型定位

- 最小可操作页面（简单 HTML/模板即可），用于**发起业务、查询结果、展示失败原因**；不追求视觉复杂度。
- 原型对应流程第 2 阶段（原型设计）证据；页面状态须有简短说明并随提交留证。

## 2. 必备页面（缺一不可）

| 页面 | 角色 | 必须可操作 / 必须展示 |
|------|------|----------------------|
| 申请与审批页 | 申请人 / 负责人 | 创建申请（原因 + 车队 V1~V5 + 间隔 10~300）；退回后修改再提交；批准/退回；**审批人=申请人被拒绝且原因可见** |
| 试点与推广页 | 运营 | 选 2 台试点、发起试点；查看试点结果；确认推广（**未全成功时按钮操作被拒绝并显示原因**）；停止未发送部分 |
| 逐车进度页 | 运营 / 负责人 | 每车：发布前值、期望值、生效值、版本号、状态（未下发/已下发待回执/成功/失败/超时/未确认）与原因；**不得只显示活动总状态** |
| 车辆模拟页/接口 | 模拟车辆 | 认证拉取配置；上报成功/失败；可触发：离线晚拉取、迟到回执、旧版本回执、重复回执、跨车身份、鉴权失败 |
| 恢复与核查页 | 负责人 / 运营 | 批准恢复；创建恢复版本（更高版本、目标 60s）；逐车恢复结果；**有未确认项时禁止显示"全部恢复"**；完成登记 |

## 3. 失败可见性要求

所有拒绝与失败必须**在页面上可见且可解释**，至少包括：审批退回原因、审批人=申请人拒绝、试点门禁拒绝、回执拒绝（未知版本/跨车/鉴权失败/重复）、越权拒绝。禁止只把失败写进日志而页面无感知。

## 4. 五组必演场景（原型须能完整走通）

1. 正常推广：申请 → 审批 → 两台试点成功 → 推广三台 → 逐车核查 → 记完成。
2. 审批与试点分支：退回修改；试点一车失败或超时 → 暂停 → 负责人停止 → **未试点车收不到配置**（须演示）。
3. 恢复分支：部分车已生效 → 停止 → 批准恢复 → 下发更高版本 → 区分已恢复与未确认。
4. 网络分支：离线晚拉取、旧回执晚到、超时后成功、重复回执、跨车身份——生效状态均不混淆。
5. 结果核查：页面同时可见成功、失败和未确认车辆的逐车记录。

## 5. 范围边界（禁止实现）

- 不做：真实车载协议、真实车辆控制、固件升级/OTA、多配置项组合、按车型/区域/时段的复杂策略、车队增删与多车队管理、安全日志配置。
- 页面上出现的任何"额外功能"按钮若无题面依据，一律不加。
