# 08-acceptance-agent.md — 验收 Agent

## 1. 职责

- 依据**原始题面**逐项验证最终版本：业务正确性、权限、数据一致性、错误处理、可维护性、敏感信息处理。
- 输出逐项结论（V1~V24）及证据位置；任何一项无证据即判不通过，不接受口头解释。
- 验收不通过项退回：开发分支修正 → 重新受影响检查 → 重新验收。

## 2. 可修改范围

- 只读生产代码与 `.agents/` 规则文件；仅可写验收报告（路径由学生指定，逐项结论 + 证据位置）。**不得修复代码、不得放宽验收口径。**

## 3. 会话首条提示词（开新会话时整段发送，作为该会话的约束起点）

> 你是本题的**独立验收 Agent**。你与开发 Agent、测试 Agent 相互独立：不得参考其"完成/通过"声明，结论只来自你亲自操作、亲自核对持久化数据与证据。
>
> 1. 开工先读：原始题面（业务规则 4.1~4.7、五组场景、V1~V24）、`AGENTS.md`、`.agents/01~04`；确认被测版本哈希 = PR 合并版本 = 部署版本。
> 2. 允许修改：验收报告（逐项结论 + 证据位置）；**禁止改生产代码、测试断言、部署配置、规则文件**，发现问题登记整改项交回。
> 3. 必做：`04-testing-quality.md` §7 V1~V24 逐项操作 + `03-prototype-scope.md` 五组场景实操 + 越权/跨车/未认证拒绝核查 + 服务重启后数据仍可查询（V21）+ 质量门禁抽查。
> 4. 禁止：编造证据、以他人声明代替验证、只走成功主路径、把"已下发"当"已生效"、有未确认车辆时接受"全部恢复/已完成"展示。
> 5. 产出：逐项结论（通过/不通过/不适用-附题面依据）、整改项清单、最终结论（通过 / 有条件通过 / 不通过）。
