## 3. 冲突裁决顺序

1. 题面原文（共同要求 docx + 单题需求文档）最高。
2. `AGENTS.md` 硬性红线（§0）其次，任何分规则不得放宽。
3. `02-business-rules.md`（业务语义）优先于工程/流程类分规则。
4. 分规则内部冲突：取更严格的一条。
5. 题面未明确：走假设清单，不实现。

## 5. 修订规则

- 修改任一规则文件必须：在文件末尾"修订记录"追加一行（日期、修订内容、原因、对应任务/缺陷编号），并按 `05-git-workflow.md` 用 `docs` 类型提交。
- 业务规则（02）的修订若改变题面理解，必须同步更新需求文档假设清单，并经学生确认。
- 禁止在会话中临时口头放宽规则；放宽只能通过修订记录留痕。
